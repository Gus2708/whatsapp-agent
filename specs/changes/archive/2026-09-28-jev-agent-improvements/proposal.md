# Proposal: jev-agent-improvements

## Intent

The WhatsApp customer service bot for Ferretería El Serrucho routes all non-clarification messages through a heavy LangChain agent (`AI Agent` on OpenRouter), inducing 2–5 seconds of latency and substantial token consumption even for fixed queries (business hours, location, payment methods, social greetings). Additionally, multi-product quote requests are occasionally subject to fragmented searches before reaching the quote tool.

This proposal promotes Jev from passive observation (`shadow`) to an active **Guarded Fast Router**:
1. Intercept institutional information (`store_info`) and social conversational turns (`general`) in sub-500ms without invoking the heavy LLM.
2. Direct multi-item quote inquiries (`quote`) straight to `hacer_presupuesto_tool`.
3. Provide robust fail-safe fallback to the standard `AI Agent` on low confidence (<0.85), transport errors, or standard product inquiries (`product_inquiry`).

## Scope

### In Scope

- **Institutional Fast-Path (`store_info`)**: Authoritative, instant response for opening hours, physical address in Maracaibo, and accepted payment methods (BCV official exchange rate, cash USD, Zelle, Pago Móvil).
- **Social Fast-Path (`general`)**: Immediate warm Rioplatense greetings and courtesies with zero token cost.
- **Quote Routing (`quote`)**: Structured handoff to `hacer_presupuesto_tool` avoiding fragmented catalog queries.
- **Fail-Safe Confidence Thresholding**: Strict confidence gate (threshold 0.85); any uncertainty falls back smoothly to the existing `AI Agent`.
- **Comprehensive Verification**: Regression and integration test suite asserting zero breaking changes to the catalog search engine and n8n topology.

### Out of Scope

- Removing or replacing the LangChain `AI Agent` for standard product inquiries and complex multi-tool conversations.
- Direct fine-tuning of the upstream Jev foundation model (inventory and prices remain strictly in Supabase).
- Live payment gateway execution or automated cart checkout.

## Capabilities

### New Capabilities

- `fast-router`: Instant sub-500ms dispatcher for `store_info` and `general` intents, bypassing the LLM.
- `quote-dispatcher`: Intent-aware pre-formatter routing multi-product requests directly to `hacer_presupuesto_tool`.

### Modified Capabilities

- `conversation-context`: Expanded to support multi-intent metadata and route tokens generated by Jev.
- `jev-shadow`: Transition from passive telemetry-only node to an active decision node with guarded pass-through.

## Approach

Implement a multi-tier routing architecture:
1. **Tier 1 (Instant Deterministic & Jev Fast-Path)**:
   - When message is classified as `store_info`, `general`, or `human_request` with confidence >= 0.85, emit an immediate pre-formatted response or handoff token.
   - For `quote` intent, format the input for `hacer_presupuesto_tool`.
2. **Tier 2 (Graceful LLM Fallback)**:
   - For `product_inquiry`, `unclear`, low confidence (<0.85), or transport exceptions/timeouts, execute the normal LangChain `AI Agent` flow unchanged.
3. **Data Integrity & Safety**:
   - Zero state mutation or inventory modification inside the router; catalog queries continue to use `buscar_productos` with Supabase popularity ranking.

## Affected Areas

| Area | Impact | Description |
|---|---|---|
| `lib/jev-shadow.js` | Medium | Promote classification output to supply route decisions when confidence >= 0.85. |
| `lib/conversation-context.js` | Low | Coordinate fast-path tokens for institutional info and quote preparation. |
| `n8n_workflow.json` | Medium | Add fast-path branching in `Needs Product Clarification?` / router node before `AI Agent`. |
| `scratch_live/` | Low | Keep standalone n8n executable code nodes in sync. |
| `tests/` | Medium | Add comprehensive TDD tests for fast-path routing and threshold validation. |

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| False positive on compound query (e.g. asking for paint AND business hours) | Low | Jev prompt and rubrics strictly prioritize `product_inquiry` when product tokens are present; any ambiguous turn falls back to the full LLM agent. |
| External Jev API latency or outage | Low | Fail-closed timeout (1,500 ms) and error catching already in place; immediately defaults to the LLM agent without user disruption. |
| Outdated store information | Low | Store info is centralized in a single versioned template in `lib/` with optional Supabase override. |

## Rollback Plan

1. Set `JEV_MODE=off` in the environment to immediately revert Jev to disabled state; all traffic flows through the existing `AI Agent`.
2. The pre-existing workflow baseline (`workflows/production-baseline.json`) remains completely intact and can be restored with `node scripts/build_workflow.js`.

## Success Criteria

- Customer queries regarding business hours, location, or payment methods respond in < 600 ms without contacting the OpenRouter LLM.
- Multi-product quote requests trigger `hacer_presupuesto_tool` directly without failed individual product searches.
- Full catalog regression suite (`node rag.js regresion`) maintains 0 false negatives across 86 cases.
- 100% of unit and integration tests pass cleanly (`npm test`).
- `sdd check` passes with zero errors.

## Open Questions

None. The threshold of 0.85, the fail-closed fallback, and the store template structure have been established during technical exploration.
