# Product candidate qualification pilot

`buscar_productos_tool` can optionally send ambiguous search results to Jev through Vercel AI Gateway. PostgreSQL and the existing search code still select products, handle stock and measure rules, and calculate prices and sales popularity. The qualifier receives only the customer request and up to four displayed product descriptions in one `POST https://ai-gateway.vercel.sh/v1/evaluate` call. It never receives prices, stock, sales totals, or a database credential. Exact lexical matches and hard measure mismatches do not invoke it.

The independent `JEV_PRODUCT_QUALIFIER_MODE` setting is `enforce` by default in the production Docker Compose configuration. `shadow` observes scores without changing the tool output and logs aggregate counts plus bounded catalog codes and scores for calibration; it logs no customer text. `enforce` removes candidates below 0.50, retains 0.50–0.84 for confirmation, and retains scores at or above 0.85. It does not promote an approximate match to `exact`; existing confirmation instructions remain in force. If every displayed candidate is removed, the existing `missing`/`handoff` decision asks an employee to review the request. Missing credentials, timeout, malformed responses and gateway errors leave the existing search result unchanged. Each request has a 1,200 ms timeout, redirects disabled, an 8 KiB request cap and a 16 KiB response cap.

Set `JEV_PROVIDER=vercel`, `JEV_MODEL=typesafe-ai/jev`, and `AI_GATEWAY_API_KEY` in the remote host's private `.env`. The live workflow and production Compose now use `enforce` as requested. Collect labeled examples of correct and misleading matches, and compare gateway scores against human judgments while refining the thresholds. They are provisional settings, not measured probabilities of correctness. Set `JEV_PRODUCT_QUALIFIER_MODE=shadow` to observe without filtering or `off` to disable qualification. This setting does not alter the separate `JEV_MODE`, `JEV_ROUTING_ENABLED`, or `JEV_ROUTING_SCOPE` controls for conversational routing.

Run `node --test tests/jev-product-qualifier.test.js`, `node scripts/check_sources_sync.js`, and `node scripts/check_workflow_sync.js` after editing. `node scripts/build_conversation_sources.js` embeds the tested helper in the standalone search source; `node scripts/build_workflow.js` produces the inactive n8n export. Neither command deploys it. Roll back qualification by setting `JEV_PRODUCT_QUALIFIER_MODE=off` and recreating n8n to load the environment change.
